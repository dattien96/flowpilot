# FlowPilot - Workflow Artifacts

This document defines how the system handles **Artifacts**, which are the structured outputs generated by each step in a workflow.

## 1. What is an Artifact?
An artifact is the tangible output produced when an AI Agent completes a workflow step. Depending on the step, artifacts usually take the form of Markdown (`.md`) documents or JSON payloads.

Examples of artifacts include:
- Product Requirement Documents (PRD)
- Technical Specifications
- Implementation Plans
- Task Breakdowns & Master Schedules
- Root Cause Analysis Reports

## 2. Artifact Lifecycle & Management

To ensure context is never lost and decisions are fully traceable, artifacts are managed as first-class citizens within the FlowPilot ecosystem.

### 2.1 Persistent Storage & History Log
- **Automatic Saving:** The output of every workflow step is automatically saved as an artifact file upon completion.
- **Version History:** Every time a step is re-run or an artifact is updated, the system maintains a complete history log. Users can browse previous versions of an artifact to understand exactly how the requirements, tech specs, or plans evolved over time.

### 2.2 Notes and Annotations
- **Human Collaboration:** Users (Developers, Leaders, or PMs) can add manual notes and annotations directly to an artifact. 
- **Auditability:** This acts as a permanent audit trail, capturing *why* certain architectural decisions were made or why a PM approved a specific edge case before coding started.

### 2.3 Synchronization & Export
Because artifacts represent highly valuable project documentation, they are not locked into the FlowPilot dashboard:
- **Local Sync:** Artifacts can be synced directly to the local project workspace (e.g., saved inside an `.artifacts/` folder). This allows teams to commit their PRDs and Implementation Plans into Git alongside the source code.
- **Cloud Sync:** Users can configure the system to automatically backup and sync artifacts to a cloud drive using the **Driver Google MCP**. This ensures that non-technical stakeholders have continuous, easy access to the latest project specs without needing to access the developer environment.

## 3. Artifact Memory

Artifacts also feed the workflow memory system defined in [SS-09](./SS-09-Artifact-Memory-Context-Retrieval.md).

The raw artifact file remains the single source of truth. After an artifact is saved, FlowPilot generates a shorter structured working memory record from it. That working memory is stored in Supabase Postgres, embedded for vector search, and later selected by the Context Resolver when building prompt memory for a workflow step.

This means:
- raw artifact = durable memory and audit source
- structured memory = searchable working memory
- prompt memory = selected context sent to the AI model
