# CA-427 — Enforce Frozen Scope At Coder Gate And Amendments (Task-266, CP-55 P-4)

## Scope

Implemented [Task-266](../requirements/08-Task/done/Task-266-Enforce-Frozen-Scope-At-Coder-Gate-And-Amendments.md) (P-4 of [CP-55](../requirements/07-Coding-Plan/done/CP-55-Flow-First-Preflight-Contract-Context-Retrieval-And-Canonical-Acceptance.md)): a new, disjoint branch in `runChildArtifactOutputGateAtEpoch` that loads the `FrozenContractRecord` CP-55 P-3 bound to an `agent.code` writer's step, hard-blocks if none exists or if the writer touched anything outside `DeclaredPaths` (diffed against the record's own `BaseSHA`), and never routes through the legacy declared/inferred `Contract` path at all. Adds `changecontract.AmendFrozenContract` for scope-widening retries.

A dedicated Claude-agent review (per operator direction, replacing Codex for this phase) found 2 Critical, 5 Important, and 4 Minor findings against this original implementation, including one real security hole: the doc/audit-path filter (added to fix the original pass's own self-caught bookkeeping-false-positive) exempted the entire `.flowpilot/**` tree and every `*.md` file, which would have let a writer silently rewrite its own gate rules (`.flowpilot/settings/flow-rules.json`, disabling every rule judging it) or forge its own frozen contract record directly, with zero drift ever detected — and one fail-open bug: a git-observation failure against the frozen baseline degraded to trusting AI-self-reported changed-file paths (frequently empty), letting an unverified turn pass. Both Critical findings, plus four of the five Important findings, are fixed in this same note — each fix verified via mutation testing (temporarily reverted, the corresponding test confirmed to fail, then restored to pass) rather than merely asserted. See "Claude-agent review pass 1" under Design notes and Verification below for the complete accounting.

## Design notes

- **The new branch is a hardcoded check, not a `flowgate` rule, by deliberate design.** Reusing the existing `r-scope` rule (or its `ScopeOutOfScopePaths`/`ScopeHighSeverity` `TurnResult` fields) was considered and rejected: `r-scope`'s default action is `warn`, and `checkRule`'s severity-downgrade logic only ever downgrades a *configured* `block` to `warn` when not `HighSeverity` — it has no upgrade path from `warn` to `block`, and reusing the same rule ID would let a user's own `.flowpilot/settings/flow-rules.json` (which legitimately governs Normal chat's lenient r-scope) also loosen Flow's supposedly-hard guarantee. A separate, unconditional, non-configurable check — mirroring the existing git-commit-detection block a few lines below it in the same function — is what actually gives Flow the strong guarantee the spec asks for.
- **Caught by testing, not by design review: freezing a contract is itself a workspace mutation.** `TestFlowCoderUsesFrozenScopeInsteadOfFinalMessage` failed on first run with `flow scope drift: ... .flowpilot/contracts/frozen_contracts.ndjson` — `changecontract.FreezeContract`/`SaveFrozen` (Task-264/265) write into the exact same workspace this gate then diffs, and a naive comparison flagged that write as the coder's own drift. Since this reproduces on *every* `agent.code` completion (the freeze always happens, in every real flow), this would have been a 100%-reproducing false-positive block in production, not an edge case.
- **CORRECTION (Claude-agent review pass 1, Critical — Finding 2): the original fix for the bullet above was itself a security hole.** It filtered via `flowgate.IsDocOrAuditFile`, which exempts the *entire* `.flowpilot/**` tree and every `*.md` file — not just the two files the freeze mechanism actually writes. Under that rule, a writer could silently rewrite `.flowpilot/settings/flow-rules.json` (disabling every gate rule that would otherwise judge it, including this one) or forge `.flowpilot/contracts/frozen_contracts.ndjson` directly with an attacker-chosen `DeclaredPaths`, and neither write would ever register as drift. Fixed: `changecontract.IsFrozenStoreBookkeepingPath` recognizes only the two exact files `FrozenStore` itself writes (`FrozenStoreBookkeepingPaths()`); every other `.flowpilot/**` path and every doc/audit file is now fully subject to scope enforcement. **Verified via mutation testing three times over**: the original filter's revert/restore cycle from the original pass is superseded by two new tests (`TestFlowScopeDriftDetectsRewrittenGateRulesFile`, `TestFlowScopeDriftDetectsForgedFrozenContractFile`) that were confirmed to fail against the reviewed-and-flagged `IsDocOrAuditFile` version and pass against the fix.
- **CORRECTION (Claude-agent review pass 1, Critical — Finding 1): a git-observation failure against the frozen baseline failed open, not closed.** The original code, on `ObserveGitDiffSince` erroring (e.g. the frozen `BaseSHA` no longer resolves after a rebase/reset/re-clone), degraded to `fin.ChangedFiles` — provider/AI-tool-call-self-reported paths, frequently empty. An empty list there meant zero drift detected, i.e. the turn passed having verified nothing — exactly the ground truth this whole check exists to establish, and the opposite of this same function's own established fail-closed contract for the identical situation forty lines earlier (BUG-288 P1-17/V10R4 P1). Fixed: the observation-error branch now blocks + escalates, matching that existing precedent exactly. **Verified via mutation testing**: `TestFlowCoderBlocksOnUnobservableFrozenBaseline` (new — freezes against a SHA that does not exist in the repo, so the diff command itself fails) was confirmed to fail against the fail-open version and pass against the fix.
- **Addition (Claude-agent review pass 1, Important — Finding 3): enforcement no longer silently skips when live topology fails to resolve the writer node.** The original gate condition was `isCodeWriterNode` alone (`flowNodeForRun` resolving the node AND its behavior reading `agent.code`) — a runner restart, a topology reload mid-flow, or any other reason that in-memory lookup fails would silently skip frozen-scope enforcement entirely for a step a frozen contract really was bound to, the exact "let an unbound write through" failure this check exists to prevent. Fixed: the coder-step id (`rs.label`, falling back to `rs.stepID`) is looked up against `FrozenStore.GetFrozenForStep` unconditionally; enforcement now fires whenever `isCodeWriterNode` is true **or** a frozen record actually exists for that exact step — deriving the guarantee from durable storage, not volatile in-memory topology. A step that was never frozen (every existing `agent.delegate` flow) still correctly skips enforcement, since `frozenOK` stays false for it either way. **Verified via mutation testing**: `TestFlowCoderEnforcedEvenWhenLiveTopologyUnresolved` (new — clears the parent's `activeFlowNodes` before the coder's turn) was confirmed to fail against the `isCodeWriterNode`-only version and pass against the fix.
- **Addition (Claude-agent review pass 1, Important — Finding 4): `AmendFrozenContract` now saves the new version before marking the old one superseded, not after.** The original order left a window where a crash or error between the two calls left the old version superseded with no active successor — `GetFrozenForStep` returns the highest-version *active* record, so `SaveFrozen` failing after `AppendStatus` succeeded meant the step could never resolve an active frozen contract again, permanently blocking it with no recovery path (the store is append-only; nothing can un-supersede a status event). Reordered: `SaveFrozen(amended)` now happens first, so even a crash immediately after it still resolves correctly (both versions active, but `GetFrozenForStep` picks the higher one) — `AppendStatus` marking the old one superseded is then just cleanup, not load-bearing for correctness.
- **Addition (Claude-agent review pass 1, Important — Finding 5): `AmendFrozenContract` now rejects a non-concrete widen path explicitly instead of silently dropping it.** `NormalizeDeclaredCodePaths` silently filters out any path that is not a "concrete code target" (no extension — `Makefile`, `Dockerfile`, `LICENSE` — or a doc/glob/flag-like entry). The original `AmendFrozenContract` unioned `additionalPaths` into the existing declared set and normalized *after* the fact, so a caller asking to widen scope to include e.g. `"Makefile"` got back `existing` unchanged with a **nil error** — indistinguishable from "you didn't need to widen anything." Composed with Finding 3's drift-then-amend flow, this would have looped a legitimate scope-drift retry forever with no actionable signal (block → attempt amendment for `Makefile` → silent no-op → retry → same block). Fixed: every non-blank `additionalPaths` entry is checked against `IsConcreteCodeTarget` up front; a non-concrete entry now returns an explicit error naming it. `TestFlowContractAmendmentRejectsNonConcreteAdditionalPath` (new, both in the runner test file and in the new `frozen_scope_test.go`) pins this directly. The secondary point in the same finding — `sameStringSet` comparing a normalized `union` against a *raw* `existing.DeclaredPaths` — is also fixed: both sides are now normalized before comparison, so a hypothetically un-cleaned stored record (e.g. from an older schema) cannot cause a spurious "changed" result.
- **`TestNormalChatKeepsLegacyInferredContractBehavior` needed an explicit rules override to isolate what it's actually testing.** The default `r-contract` rule's action is `reprompt` for any inferred-only (undeclared) turn — by design, inference is tolerated for scope-diffing purposes but does not itself satisfy the "declare before you edit" nag. Under `DefaultRules()`, `prepareChangeContract`'s inferred result is therefore correctly *never* committed via `commitChangeContract` on the first attempt (commit only happens on zero violations, or on the final warn/approve fallback — never on `reprompt`). This is 100% pre-existing legacy behavior, unrelated to and unchanged by this task. The test downgrades every doc-scope rule except `r-contract` (set to `warn`) via a scoped `.flowpilot/settings/flow-rules.json`, so it can isolate and prove the one thing actually in scope here: that an agent.delegate child's inferred Contract still gets computed and persisted, unaffected by the new `agent.code`-only branch.
- **`TestNormalChatKeepsLegacyInferredContractBehavior` needed an explicit rules override to isolate what it's actually testing.** The default `r-contract` rule's action is `reprompt` for any inferred-only (undeclared) turn — by design, inference is tolerated for scope-diffing purposes but does not itself satisfy the "declare before you edit" nag. Under `DefaultRules()`, `prepareChangeContract`'s inferred result is therefore correctly *never* committed via `commitChangeContract` on the first attempt (commit only happens on zero violations, or on the final warn/approve fallback — never on `reprompt`). This is 100% pre-existing legacy behavior, unrelated to and unchanged by this task. The test downgrades every doc-scope rule except `r-contract` (set to `warn`) via a scoped `.flowpilot/settings/flow-rules.json`, so it can isolate and prove the one thing actually in scope here: that an agent.delegate child's inferred Contract still gets computed and persisted, unaffected by the new `agent.code`-only branch.
- **`AmendFrozenContract`'s no-op-on-no-new-paths behavior is set-based, not order- or count-based.** `sameStringSet` sorts both slices before comparing, so `AmendFrozenContract(rec, []string{})`/`(rec, nil)`/`(rec, <a subset of rec.DeclaredPaths>)` all correctly report "nothing new" and return `existing` byte-identical (same `ContractID`, same `Version`) — `TestRetryWithoutNewPathsReusesFrozenVersion` pins the `nil` case directly; the store's own `ListVersionsForStep` count (still 1) is asserted, not just the returned record's fields, so a bug that minted a second version but returned the *old* one by mistake would still be caught.
- **`TestFlowCoderComputesWrittenPathsAgainstFrozenBaseline` is a genuinely discriminating test, not just a happy-path check.** It deliberately sets the child's `turnStartGitHead` to a *later* commit (`head1`, which already includes the out-of-scope file) while the frozen record's own `BaseSHA` is the earlier `head0` — if the implementation used `turnStartGitHead` instead of `rec.BaseSHA` (an easy mistake, since the two are normally the same commit and either would "work" in the common case), the diff-since-`head1` would show nothing and the test would incorrectly pass; the diff-since-`head0` correctly shows the out-of-scope commit and the test asserts a block. Review confirmed this test genuinely discriminates by tracing the mutants directly rather than re-asserting the claim.
- **Accepted/deferred, not fixed in this pass (Claude-agent review pass 1):**
  - **Finding 6 (written-path normalization asymmetry) is substantially closed as a side effect of the Finding 1 fix, not separately addressed.** The specific risk the finding named — `fin.ChangedFiles` paths being absolute or differently-cased and false-positive-blocking a compliant coder — required the fail-open fallback path to be live; removing that fallback (Finding 1) removes the scenario. `normalizeScopePath` now also applies `path.Clean` as a cheap, general hardening (paths.go-style), but a full shared normalizer between `NormalizeDeclaredCodePaths` and the written-path side was judged unnecessary scope now that the asymmetric input source is gone.
  - **Finding 7 (`AmendFrozenContract` has no production caller; the spec's "amendment transition" is not wired end-to-end)**: correct as identified, not fixed here. Wiring it into an actual retry/escalation UX is explicitly carried forward as a CP-55 follow-up (Task-266 Open Questions) rather than rushed into this pass alongside the security/correctness fixes above.
  - **Finding 10 (every gate call re-opens and re-parses the FrozenStore, including on a rejected turn)**: correct, Minor, accepted — the store is cheap at current scale, and holding one instance on the service is a reasonable future optimization, not a correctness concern.
  - **Finding 11 (the drift window is "everything since freeze," not "everything this turn wrote")**: correct as identified; recorded as an explicit open question (Task-266) for whichever slice wires real retry orchestration, rather than silently resolved either way.
