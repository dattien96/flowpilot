# CA-1163 — BUG-632 red test baseline superseded by verified green oracle evidence

## Context

Live run-174243: `.flowpilot/guard/test_baseline.json` held
`suite_passed:false, green_tests:[]` captured at 20:34 during Task-032's
TDD-stub phase — an intentional intermediate red. The refresh rule
(`RefreshBaselineIfStaleContext`) only recaptures a red baseline on
clean-HEAD-moved, but a sprint's tree is dirty by construction from
scaffold until the audit commit — so the red baseline survived the whole
sprint and `gate_blind red_at_capture` warned on every code-touching
turn, feeding drift scoring that contributes to debate mounts.

The gate's own oracle (`RunOracleContext`) already runs the suite every
turn; a passing result is direct green evidence that was being discarded.

## Changes

`internal/runner/gate_blind_hook.go`:

1. `supersedeRedBaselineOnOracleGreen` — when `baseline.SuitePassed ==
   false` and the oracle's suite run this turn passed
   (`oracle.SuitePassed && oracle.EnvError == ""`), recapture the
   baseline via `CaptureBaselineContext` and return the fresh green
   baseline. Recapture (not `oracle.Passed` write-back) because the
   oracle run may have been package-scoped by `scopeTestCommand` — a
   scoped pass list is a subset and would poison the baseline green
   list. Fail-closed: env error, suite still red, ctx cancelled, or a
   still-red recapture all leave the prior baseline untouched.
2. `gateBlindBlocksTurn` signature gains `ctx` + `repoDir` and calls the
   supersede before `ClassifyGateBlind` — a verified-green turn stops
   emitting `red_at_capture` in the same turn it heals, and the
   superseded baseline carries the current (dirty) git state so
   subsequent turns see it as fresh until HEAD moves.

Semantics preserved:
- Green baselines are still frozen (V9-30) — supersede only ever fires
  on `SuitePassed == false`.
- Still-red suites keep the enforce blind block (fail-closed unchanged).
- The extra full-suite run happens once per red→green transition;
  subsequent turns find the green baseline fresh at the same
  HEAD+dirty state.
- `runValidateWithOracleIfPossible` needs no change — it maps
  `oracle.SuitePassed` directly and now reads the healed green baseline
  for its regression signal.

## Regression test

`internal/runner/bug632_red_baseline_supersede_test.go` — real-suite
fixture (`suite.sh` exit-code flip via `test-config.json`):

- `TestBug632_OracleGreenSupersedesRedBaseline` — capture red → flip

  enforce block and the red baseline (fail-closed).
- `TestBug632_GreenBaselineNeverTouched` — green baseline is never
  recaptured (frozen, same CapturedAt).

Existing gate-blind tests updated for the new signature (ctx + repoDir
params, no assertion changes).
