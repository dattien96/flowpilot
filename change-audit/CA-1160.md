# CA-1160 — BUG-626 scope-aware remediation reprompts + BUG-627 hub contract-scope write guard

## Context

Live run-174243 cascade, second layer (first layer = BUG-630/CA-1159):

1. The owner-debate remediation reprompt carried the verdict verbatim —
   including a demand to edit `VaultContainer.h`, a path the tdd contract
   had frozen read-only. The reprompt ordered something the contract
   forbids (BUG-626).
2. The hub session executed the demand itself ("I'm now the materializing
   node"): every contract-write guard binds a step label — the hub has
   neither a `parentRunID` nor a step id, so its write slid through
   (BUG-627). The planner-purity fingerprint then flagged the modified
   frozen file → restore↔remediate unwinnable loop → reprompt budget
   exhausted → escalate → run stopped.

## Changes

1. `internal/changecontract/preflight.go` — new
   `FrozenStore.ListActiveForRun(runID)`: governing record per step,
   `GetFrozenForStep` active semantics, deduplicated by step.
2. `internal/changecontract/frozen_scope.go` — new
   `IsOwnedScopePathUnder(rec, candidate, workspace)`: ReadOnlyPaths ∪
   DeclaredPaths ∪ AllowedExtraPaths match with the same normalization +
   legacy-absolute relativization as `IsReadOnlyLockedPathUnder`
   (internal helper `scopePathSetMatchesUnder`).
3. `internal/runner/hub_contract_scope_guard.go` (new) —
   `decideHubContractScopeLock`: hub-scoped (parentRunID=="") silent deny
   on file writes/execs aimed at any path owned by an active frozen
   contract for the hub's own run id. Same choke point + deny-only shape
   as `decideReproduceTestLock`/`decideScaffoldPreExistingLock`, before
   YOLO; reads and non-contract paths fall through.
4. `internal/runner/interactive_service.go` — guard wired into the shared
   approval bridge between the scaffold lock and the frozen-state guard.
5. `internal/runner/reproduce_gate.go` — command-name matching extracted
   to `commandNamesLockedPath(cmd, paths)` so the hub guard reuses it over
   the union path set (wrapper preserved for the reproduce lock).
6. `internal/runner/vibe_cp.go` —
   - `vibeDebateResumeRepromptPrompt` → method taking
     `(parentRunID, stepID, workspace, verdicts)`; when the gated step's
     governing contract has ReadOnlyPaths the reprompt names them and
     forbids edits ("belongs to the owning step's leg — state the routing
     in your completion and confirm").
   - `vibeDebateResumePrompt` const → method
     `(parentRunID, workspace)`: pins the orchestrator role ("never write
     or edit project artifact files yourself") and enumerates the union
     of contract-owned paths when contracts are active.
   - helpers `vibeFrozenReadOnlyPathsForStep`, `vibeHubContractOwnedPaths`.
7. Tests — `internal/runner/bug626_627_hub_contract_scope_test.go`
   (RED→GREEN): hub deny on read-only/declared/other-step paths, pass on
   non-contract paths + reads + read-only execs, child runs untouched,
   no-contract runs untouched; reprompt carries the scope clause only
   when a contract exists; hub prompt enumerates owned paths.
8. `requirements/09-BugFix/todo/BUG-62{6,7}-*.md` — status → RESOLVED.

## Notes / Follow-ups

- Loop break mechanics: the reprompt constraint makes the demanded
  frozen-path edit unordered; the bridge deny makes it unexecutable. The
  gated child reports routing + confirms; the tree stays clean; the
  planner-purity gate has nothing to flag; the sprint advances to the
  coder leg which owns the path.
- Provider parity: the guard sits at the provider-neutral
  ApprovalDetails choke point — no adapter changes; deny semantics are
  identical across Claude/Codex/Grok.
- `ListActiveForRun` dedup is per-step highest active version — a
  superseded contract's paths stop binding the hub the moment the
  supersede lands (correct: the new contract re-owns them).
