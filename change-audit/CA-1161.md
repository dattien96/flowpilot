# CA-1161 — BUG-629 deterministic gate-fixture cluster: oracle drift repair + auto-index opt-in escape hatch

## Context

BUG-629's "pre-existing assertion failures" cluster: nine `internal/runner`
tests failed identically on baseline `4266815f`, all asserting gate
`block`/`reprompt`/`escalate` outcomes that resolved as `warn`. The suite
being red masked regressions (manual triage cost already paid twice).

Root cause was oracle drift, not a production regression: Task-455
(`ad0b66ff`) introduced `effectiveGateMode` — a root run without
`flowEngineDriven` evaluates under `warn` regardless of the rule action,
so fixtures that re-keyed a `newP4ChildRun` onto a plain-chat parent id
(`rs.id = parent.RunID`) silently downgraded every assertion. The
fixtures modelled a flow-gated turn but skipped the latch production
sets at flow start.

One self-inflicted regression rode along: the BUG-629 auto-index guard
(`runningUnderGoTest`, CA-1159) made `TestEnsureGitNexusIndex_
AutoAnalyzesOnce` a guaranteed no-op — that test stubs the `gitnexus`
binary specifically to verify the analyze spawn.

## Changes

Production change is one line; everything else is fixture repair.

1. `internal/runner/gitnexus_autoindex.go` — test-env guard gains the
   codebase's established escape hatch: `runningUnderGoTest() &&
   FLOWPILOT_GITNEXUS_AUTOINDEX != "1"` (same convention as
   `FLOWPILOT_OPENCODE_MODELS_CACHE_PATH`, `FLOWPILOT_DEVIN_BIN`).
   Production behavior unchanged; tests that stub the binary opt in.
2. `internal/runner/gitnexus_autoindex_test.go` — `ca638StubGitNexus`
   sets the opt-in; installing the stub is itself the declaration that
   the test exercises the analyze path. All three CA-638 tests genuine
   again (spawn-once, indexed-skip, non-git-skip).
3. `internal/runner/bug460_worktree_autoindex_test.go` —
   `TestBug460AutoIndexSkipsManagedWorktree` opts in too, so it exercises
   the managed-worktree check rather than a trivial early return.
4. Enforce-capable child-leg fixtures (the production shape a gated
   coding leg actually is):
   - `task331_gate_hook_dod_test.go` — `newTask331RootRun` →
     `newTask331GatedLegRun` (real spawned child; its own comment
     admitted the root shape was pre-455 archaeology). Two DoD tests.
   - `bug425_gate_reprompt_contract_paths_test.go` — both reprompt-carry
     tests + `TestBug425RepromptGateInfersFromCarriedCodePaths` (a
     reprompted leg is a child).
   - `bug439_440_gate_contract_test.go` — `TestBug440RepromptCarry
     UnionsPartialWriteEvents`.
   - `bug514_reproduce_ask_loop_bound_test.go` — child leg + escalation
     assertion retargeted to `loopStateFor(rs.id)` (the real gated run;
     the old fixture made parent and gated run the same id).
5. Flow-driven hub fixtures (where the root shape was intentional):
   - `cp53_gate_blind_hook_test.go` — both gate-blind tests set
     `flowEngineDriven = true`; enforce mode now actually exercised
     (they were passing vacuously under warn).
   - `run200816_hub_plan_gate_and_verdict_advance_test.go` — hub fixture
     keeps `flowEngineDriven`; non-flow control case updated to assert
     Task-455's current semantic (plain root → warn, not block) with
     Task455's own tests as the pinning evidence.
   - `bug377_reprompt_strand_test.go` — reprompt delivery is a
     root-gate path; fixture became a flow-driven root with an explicit
     `r-newtest` ruleset (reprompt action survives the hub rule filter)
     for a deterministic armed reprompt.

## Verification

  TestBug440|TestBug514|TestGateBlind|TestRun200816|TestGateHook_DodComplete|
  TestBug439|TestTask455'` → **ok 5.3s** (all 9 previously-failing tests
  green; Task455's pin tests untouched).

  `TestBUG629_*` → all PASS.
- Full suite `go test -count=1 ./internal/runner/` → 25 failures vs 32
  baseline: the 9 cluster tests green; remaining failures classified —
  ~13 missing provider binaries (`opencode`/`codex` absent from PATH),
  ~3 Supabase/`SUPABASE_*` env leakage, 1 Firebase E2E (network), plus
  load-dependent tempdir flakes that pass isolated (`TestCA791`,
  `TestBug516`, `TestR7`, `TestDuplicateFreezeDelivery` re-verified
  individually). **Zero deterministic code-path failures remain.**
- `go build ./...` + `go vet ./internal/runner/` clean.
- Test-only topology changes — no gate semantics altered; warn/enforce
  production behavior untouched. The two plain-chat fixtures asserting
  pass-path semantics (`flow_pending_canonical`, provider-parity) left
  intentionally: their "not blocked + head written" assertions are
  genuine under warn.
