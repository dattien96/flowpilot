# CA-1172 — run-2062497 D12+D13: sub-agent chat lazy loading and drift-card dead clicks

## What changed

`apps/desktop/src/app/agents_focus.go` / related TUI files:

- `cmdFocusAgent` now replays the transcript TAIL (`chatReplayTailAfterSeq`,
  same as the main chat) and sets `historyLoadedAfterSeq`, instead of
  fetching every event from seq 0 (up to 8000). Opening a coder leg with 6+
  long turns rendered the full history and froze the UI.
- `focusStreamOpenedMsg` carries `HistoryLoadedAfterSeq`; the older-history
  fetch (`cmdFetchOlderHistory`) pages against the focused run's cursor, and
  a "load earlier" affordance appears above the window exactly as in the
  main chat.
- `chatRowsSig` hashes only the rendered window slice — it previously
  hashed the content of every message in the transcript on every frame,
  making each repaint O(total transcript bytes) even after load.

`apps/local-runner/internal/runner/interactive_handlers.go`:

- `handleAmendFlow` partitions the requested paths: amendable entries are
  amended, the rest are reported in a new `unamendable_paths` response
  field — a mixed batch (concrete file + submodule dir) no longer 422s the
  whole Allow click. An all-unamendable batch keeps the loud 422.

`apps/desktop` client + TUI:

- `AmendFlow` response exposes `UnamendablePaths`; the surfaced failure is
  a warning message in the transcript instead of flipping `connStatus` to
  error for a single gate rejection.

Live D13: the drift decision card looked dead because [Allow] → 422 on the
unamendable dir entry left the park standing with no visible error.

## Invariant

A focused sub-agent opens on a bounded transcript window and pages older
history on demand, and a partially-sanctionable Allow batch sanctions what
it can while reporting — not silently dropping — the rest.
