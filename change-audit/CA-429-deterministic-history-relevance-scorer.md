# CA-429 — Deterministic History Relevance Scorer (Task-268, CP-55 P-6)

## Scope

Implemented [Task-268](../requirements/08-Task/done/Task-268-Deterministic-History-Relevance-Scorer.md) (P-6 of [CP-55](../requirements/07-Coding-Plan/done/CP-55-Flow-First-Preflight-Contract-Context-Retrieval-And-Canonical-Acceptance.md)): a new, deliberately unwired pair of pure scoring/ranking functions — `ScoreHistoryEntry`/`RankHistoryEntries` in a new `internal/featurecatalog/relevance.go` — that will let a later phase (P-7) rank a feature's change-ledger history by code-locus overlap instead of by recency alone. This phase adds only the primitives and their own tests; nothing in the codebase calls them yet (`Keep symbols unused` per the phase's own spec).

A dedicated Claude-agent review found **0 Critical, 5 Important, and 7 Minor findings** — a **CONDITIONAL PASS**: the production logic itself was judged functionally correct (the 3-level ordering matches spec exactly, the comparator is a valid strict weak ordering, the code is genuinely deterministic with no map-iteration or goroutine dependency), but 3 of the original 9 spec-mandated tests were shallow enough that the reviewer constructed specific, plausible mutant implementations that passed the full suite while violating the phase's own stated invariants — including one mutant that silently reintroduces the exact BUG-266 class of nondeterminism the commit-hash tie-break exists to prevent. All 5 Important findings are fixed in this same note, each verified via mutation testing (temporarily reverted/mutated, the corresponding test confirmed to fail, then restored to pass). See Design notes and Verification below for the complete accounting; the 7 Minor findings are addressed inline or explicitly accepted/deferred.

**Claude-agent review pass 1 fix (2026-07-31):**

- `apps/local-runner/internal/featurecatalog/relevance.go` (rewritten): added `canonicalPathForOverlap` (forward-slash + `path.Clean` + trim, applied to both sides of the comparison at score time — Finding IMP-1) and extracted `buildLocusPathSet`/`scoreAgainstLocusSet` so `RankHistoryEntries` builds the locus set once and reuses it across every entry instead of once per entry (Finding MIN-3, a free perf win from the same refactor). `RankHistoryEntries` now returns `nil` for empty input, matching `changeledger.GetFeatureHistory`'s own empty-result convention (Finding MIN-6). Doc comments corrected: `CommitUnix`'s "0 is the oldest possible value" claim was factually wrong (a pre-1970 timestamp parses negative) — now describes it as a floor by convention, not construction, and documents that it diverges from `changeledger.GetFeatureHistory`'s own string-based `CommittedAt` ordering for a non-UTC-offset timestamp (Finding IMP-5). `RankedHistoryEntry`'s aliasing of `ChangedPaths` with the caller's backing array is now documented (Finding MIN-2); the "never depends on input order" claim is now qualified on `CommitHash` uniqueness (Finding MIN-1); matching is now documented as explicitly case-sensitive (Finding MIN-5).
- `apps/local-runner/internal/featurecatalog/relevance_test.go`: `TestScoreHistoryEntryCountsExactPathOverlap` now includes prefix/reverse-prefix/substring near-miss paths that a non-exact matcher would wrongly count (Finding IMP-2). `TestScoreHistoryEntryDeduplicatesPaths` now also covers a duplicated locus-side path (Finding MIN-4). `TestRankHistoryEntriesIsDeterministicAcrossRuns` rewritten to permute a 5-entry fixture (including a same-overlap, different-recency, adversarially-hashed entry) across 7 orderings and assert a pinned expected order, instead of re-running one fixed input order 20 times (Finding IMP-3, folds in Finding MIN-7). `TestRankHistoryEntriesDoesNotUseSymbolsBeforeBug323` gained a second case with `Paths` AND `Symbols` both populated and colliding, since the original case alone hit the same early-return regardless of whether `Symbols` was read (Finding IMP-4). Three new tests: `TestScoreHistoryEntryCanonicalizesPathsBeforeComparing`, `TestScoreHistoryEntryHandlesUnparseableCommittedAt`, `TestScoreHistoryEntryParsesCommittedAtAsUnixSeconds` (Finding IMP-5), `TestRankHistoryEntriesReturnsNilForEmptyInput` (Finding MIN-6).

## Design notes

- **The routing/wiring boundary is deliberate, not an oversight.** Grep across `apps/local-runner` for `ScoreHistoryEntry|RankHistoryEntries|RankedHistoryEntry|HistoryRelevance` returns matches only in `relevance.go`/`relevance_test.go` — confirmed by the reviewer independently. `HistoryRankingConfig`, `SelectHistoryEntries`, `HistorySlotRanked`, and the `feature.history` source wiring are explicitly P-7's own production changes and test signatures, not this phase's.
- **CORRECTION (Claude-agent review pass 1, Important — Finding IMP-1): the original doc comment's normalization guarantee did not hold upstream.** It claimed `entry.ChangedPaths`/`locus.Paths` both arrive "already... normalized... by the time they reach here." The reviewer traced both producers and found this false in at least two ways: (1) `runner/flow_context_hint_paths.go` deliberately *keeps* a leading `./` on a locus path built from a user prompt ("Task-246: strip trailing prose punctuation only, keep leading `./`"), so a prompt referencing `./apps/.../foo.go` would enter `locus.Paths` with the prefix intact while the ledger's own `ChangedPaths` for the same file never carries one; (2) a non-ASCII path from `git log --name-only` without `-z` can arrive quoted/octal-escaped on one side and not the other. Concretely: this would have silently zeroed the overlap score for the single most relevant commit in the ledger, with the ranking feature appearing to work while producing exactly wrong output. Fixed: `canonicalPathForOverlap` (forward-slash + `path.Clean` + trim) is now applied to both `entry.ChangedPaths` and `locus.Paths` at comparison time, inside this package, rather than trusting upstream producers to agree. **Verified via mutation testing**: reverted `canonicalPathForOverlap` to a no-op passthrough → `TestScoreHistoryEntryCanonicalizesPathsBeforeComparing` (new) failed as expected (a `./`-prefixed locus path no longer matched); restored → passes.
- **CORRECTION (Claude-agent review pass 1, Important — Finding IMP-2): the "exact overlap" test could not distinguish exact matching from prefix or substring matching.** The reviewer constructed a `strings.HasPrefix`-based mutant that passed the original fixture unchanged, because none of its paths happened to trigger a false prefix/substring match. Concretely: a future "helpful" refactor toward fuzzy path matching (e.g. to handle renamed files) could inflate scores for `src/calc.go.bak`, `src/calc`, or `vendor/src/calc.go` against a locus containing `src/calc.go`, and the entire suite would stay green. Fixed: `TestScoreHistoryEntryCountsExactPathOverlap`'s fixture now includes exactly these near-miss shapes, asserting they must NOT count. **Verified via mutation testing**: a `strings.HasPrefix`-based overlap check was substituted → the test failed (`PathOverlap = 3, want 1`); restored the exact-match implementation → passes.
- **CORRECTION (Claude-agent review pass 1, Important — Finding IMP-3): `TestRankHistoryEntriesIsDeterministicAcrossRuns` provided almost no signal.** It re-ran `RankHistoryEntries` 20 times on the *same* fixed input order and compared each run only to the first — since the function is pure and reads no global/random state, any deterministic implementation (correct or not) trivially reproduces identical output across repeated calls on identical input. The reviewer constructed an asymmetric-comparator mutant (`if i.Unix > j.Unix { return true }` in place of the correct `if i.Unix != j.Unix { return i.Unix > j.Unix }`) that violates strict-weak-ordering, and demonstrated it passes all 9 original tests, because the specific fixtures used never asked the comparator both directions on a pair where the asymmetry would show. Fixed: the test now permutes a 5-entry fixture — including a same-overlap-but-older entry with a lexicographically smaller hash than its same-overlap peers, chosen specifically to expose the asymmetric-comparator failure mode — across 7 input orderings, asserting every permutation yields one pinned expected order. **Verified via mutation testing twice**: the asymmetric-comparator mutant described above → failed on the very first permutation tried (`[0 1 2 3 4]` produced `[bbb 0aa aaa ccc ddd]`, wanted `[bbb aaa ccc 0aa ddd]`); restored → passes across all 7 permutations.
- **CORRECTION (Claude-agent review pass 1, Important — Finding IMP-4): the BUG-323 "Symbols unused" test did not actually prove Symbols is unread.** The original test set `locus.Symbols` non-empty while leaving `locus.Paths` empty, and compared against a fully zero-value locus — both hit the identical `len(locus.Paths) == 0` early-return regardless of whether `Symbols` was ever read, so the assertion was close to vacuous. The reviewer constructed a mutant that unions `locus.Symbols` into the match set only when `locus.Paths` is also non-empty, and showed it passes the original test unchanged. Fixed: added a second case with both `Paths` and `Symbols` populated, where a `Symbols` entry is chosen to collide with a path the test entry actually touched. **Verified via mutation testing**: the Paths-gated-Symbols-union mutant described above → failed (`PathOverlap = 2 with Symbols vs 1 without, want 1 both`); restored → passes.
- **CORRECTION (Claude-agent review pass 1, Important — Finding IMP-5): the `CommitUnix` fallback comment was factually wrong, its divergence from `GetFeatureHistory`'s ordering was undocumented, and it had zero direct test coverage.** "0 (the oldest possible value)" is not true — a genuine pre-1970 `CommittedAt` parses to a negative Unix value and would sort older still; `CommitUnix` (Unix seconds) and `changeledger.GetFeatureHistory`'s ordering (raw RFC3339 string comparison) can disagree for a timestamp carrying a non-UTC offset. Neither was tested: no test ever passed a malformed timestamp, and no test ever asserted `CommitUnix` against a known-correct numeric value (only that it was non-zero). Fixed: the doc comment states the true floor-by-convention behavior and the documented divergence from `GetFeatureHistory`; two new tests pin the fallback (`TestScoreHistoryEntryHandlesUnparseableCommittedAt`, four malformed inputs) and the exact parsed value/timezone-invariance (`TestScoreHistoryEntryParsesCommittedAtAsUnixSeconds`).
- **Addition (Claude-agent review pass 1, Minor — Findings MIN-1 through MIN-7):** MIN-1 (input-order-independence claim qualified on `CommitHash` uniqueness) and MIN-5 (case-sensitivity documented) are doc-only fixes; MIN-2 (`ChangedPaths` aliasing) is now documented rather than fixed, since deep-copying on every rank would cost more than the aliasing risks in practice; MIN-3 (locus set rebuilt per entry) is fixed as a natural side effect of the IMP-1 refactor (`buildLocusPathSet` is now called once per `RankHistoryEntries` call, not once per entry); MIN-4 (locus-side duplicate paths untested) is closed by an assertion appended to `TestScoreHistoryEntryDeduplicatesPaths`; MIN-6 (nil-vs-empty-slice convention) is fixed — `RankHistoryEntries` now returns `nil` for empty input, matching `changeledger.GetFeatureHistory`; MIN-7 (`TestRankHistoryEntriesCommitHashBreaksCompleteTie` tested only one input permutation) is subsumed by the IMP-3 permutation-based rewrite, which supersedes it.
- **Not fixed, explicitly accepted (per the reviewer's own recommendation):** none of the 7 Minor findings were left entirely unaddressed — see above for how each was resolved or judged not worth a structural change.
