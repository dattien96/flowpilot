FlowPilot Sub-Agents — UI Frames & Architecture

A first-class Agent abstraction layered on top of the existing interactiveRun + provider-adapter machinery. Every sub-agent is a normal chat run (Codex / Claude) tagged with a parent and a role — so spawning, streaming (SSE), and persistence reuse what already ships. Below: the data flow, then 5 interactive UI frames matching the desktop theme.

◇ Architecture & data flow ① Main chat · agent running ② Inside a sub-agent · back-to-main ③ Spawn-agent dialog ④ Orchestration board (coder ‖ reviewer) ⑤ Right-panel states

◇ Architecture & data flow

A sub-agent run is just an interactiveRun with parentRunId + agentName + role. The model spawns one by calling a spawn_agent tool (same mechanism as the existing ask_user tool); the user can spawn one from the UI. An AgentOrchestrator owns the dependency graph + message bus (reviewer waits on coder → feeds back → coder continues).

new orchestration code extended / reused PHASE 1 chat PHASE 2 flow
Why this is the right cut: the runner already streams one provider session per run over SSE and persists/resumes it. A sub-agent doesn't need a new transport, a new event schema, or a new adapter — it needs identity (parent + role) and a coordinator. Everything else (Codex/Claude streaming, approvals, token usage, Drive sync, cross-PC resume) is inherited for free.

Interaction rules
  • Highlight: while an agent runs, its timeline items carry a left accent border in the role color; the header shows "N agents running".
  • Click to focus: selecting a card swaps the Timeline to that run's SSE stream + shows the back-to-main breadcrumb.
  • Back to main: always one click; the main agent's stream is never lost (it streams in the background).
  • @mention: typing @coder … in the composer routes the message to that child run.
  • Promote: a child's answer can be "promoted" into the main timeline as a handoff artifact.
  • Parallel: coder + reviewer run at once; the reviewer's dependsOn gates when it consumes the diff.
  • Feedback loop: reviewer "changes-requested" re-opens the coder's turn with the feedback as input; loops to a round cap.
Phase split
  • PHASE 1 chat ad-hoc spawning, in-memory orchestrator, NDJSON/Drive persistence. Ship the UI + spawn_agent + parent/child.
  • PHASE 2 flow dependency graph + bus become Supabase rows (agent_runs, agent_messages); reviewer-gate replaces human approval in workflows.
